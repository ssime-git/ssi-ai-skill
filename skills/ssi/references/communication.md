# Communication

Lead with the result or the useful finding. Give enough evidence and explanation for the reader to assess it.
Use the user's language. Prefer short, concrete paragraphs and familiar words.
Do not repeat phase labels, progress bars, time estimates or "no need for you" in every message.
A brief task can finish in one concise response. Longer work needs updates when a meaningful finding or decision changes the next step.

Ask only blocking questions, with succinct options when helpful. Explain the consequence of the choice.
An answer already given remains valid; do not ask again because the workflow changed phase.
Describe checks accurately: executed, reviewed, reported or not verified. Include limits that matter.
Keep logs in files and quote only the relevant failure. Never describe absent CI as green CI.

For a PR, keep required unresolved work in its Open items list; finish it before claiming completion.
Deferred optional improvements belong in the handoff or a useful follow-up Issue, not in the current task's blocking checklist.
